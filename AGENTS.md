# PlantPulse — Project Instructions

## Before working
- Read the README and inspect the relevant project files.
- Identify the actual technology stack, package manager and available commands.
- Follow the existing architecture and coding conventions.
- Ask for clarification when a requirement is ambiguous and the decision could significantly affect the project.

## Development principles
- Prefer small, focused and maintainable changes.
- Reuse existing modules, components and utilities where appropriate.
- Avoid unnecessary dependencies and duplicated logic.
- Preserve existing functionality unless a change is explicitly required.
- Keep interfaces, types, schemas and documentation consistent.

## Verification
- Run relevant tests, linters, type checks or build commands when available.
- Report which checks were actually executed and their results.
- Never claim success without evidence.
- Clearly distinguish confirmed bugs from potential risks.

## Safety and collaboration
- Never expose secrets, tokens, credentials or private environment variables.
- Do not commit, push, deploy, run destructive migrations or overwrite important data without explicit authorization.
- Avoid conflicting edits when multiple agents work on the same task.
- Require an independent review for significant or security-sensitive changes.
- Do not treat another agent's conclusions as automatically correct.

## Project-specific rules
- Discover the actual architecture and conventions from the repository.
- Do not assume the project uses any particular framework, language, database or deployment platform until verified.
- Update this section when project-specific requirements are confirmed.
